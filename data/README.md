### RDR/PUN device data

This folder contains data files for RDR/PUN device. 
Defaukt names for data files are:
for RDR: data/data.rdr
for PUN: data/data.pun.<timestamp>
Don't delete this folder as it is used also for tests. Tests files are created here and then deleted afterwards.
Deleting this folder will cause that some tests will fail as the test files cannot be created in nonexisting folder.



**Examples:**

**Transferring files to CP/M system**

To upload the file to cp/m operating system pip command can be used together with UR1, UR2, UP1 or UP2 user devices. 

As PIP can process only text files, to transfer binary data, intelhex format can be used

File can be translated to intelhex format with external command or with GUI built in ih/ihex command. Just make sure that start adress is 100H. Here are the steps for transfer the file:

1. transform binary file to intelhex format via external utility or via GUI built command ih/ihex. Let say we want to transfer a file *sc2.com* placed in data folder. By using internal GUI command we can transform it to intelhx formar:
   
   `if 0x100 data/sc2.com` 
   
   it will create the file sc2.com.hex. This step doesn't have to be executed for regular text files.

2. rename the file that will be transferred to cp/m machine to *data.rdr*.

3. From CP/M's terminal use PIP command to transfer the file to specific disk, like below:
   
   `D>A:PIP SC2.HEX=UR1:`
   
   This will transfer file *data.rdr* prepared in the previous step and name it *sc2.hex*. If the file is plain text file, let say *test.asm* we are done and we have the file in CP/M system. But if the file is binary file, as our example of *sc2.com* we have to translate it from intelhex to binary. CP/M has a utility LOAD that can be used in this case.
   `D>A:LOAD SC2`
   
   This will create SC2.COM file. And it is basically what we wanted in the case of .COM file. Generation of .COM file is default extension generated by LOAD command. If different extension is required, we can just rename the file and give it a new extension. For example if we transfer file sc2.ovl file, then we have to rename sc2.com file to sc2.ovl:
   `D>A:REN SC2.OVL=SC2.COM`



**Transferring file from CP/M system.**

This procedure is similar to transferring file to CP/M system because again INTELHEX format needs to be used for transferring binary files.

Again PIP command can be used for the transfer as in following examples:

Let say we want to transfer file named HLT.ASM from CP/M. We can use PIP command:

`D>A:PIP UP1=HLT.ASM,EOF:`

Note the *EOF:* device name added to PIP command. This is necessary and it will cause that END OF FILE is sent and the file is closed. The resulting file has the following name:

*data.pun.<timestamp>*. Example of concrete file: *data.pun.20260413_003652*. 

We can also transfer multiple files and close the resulting file only after the last file is transferred. For example, let's have the following files, sc2.ov1, sc2.ov2, sc2.ov3 and we want to crate one resulting file. The following command can be used:

`D>A:PIP UP1:=SC2.OV1,SC2.OV2, SC2.OV3,EOF:`

Or we can use multiple PIP commands and close the file just after the last file has been transferred as in the following example:

`D>A:PIP UP1:=SC2.OV1`

`D>A:PIP UP1:=SC2.OV2`

`D>A:PIP UP1:=SC2.OV3,EOF:`

And again if we transfer a file in INTELHEX format this needs to be translated to binary if needed.
